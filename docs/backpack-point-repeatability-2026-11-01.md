# 书包固定像素：SDK XYZ 重复性

## 范围与方法

用户明确同意开始固定点测试，并决定现阶段延后量尺对照。因此本轮不使用独立物理距离参考，绝对准确度保持未验证。
设备、SDK 与 Python 环境沿用项目已有版本，未增加 SDK、ROS 或系统 Python 包；本轮只采单深度流。

用户在相机后移并放稳后指认的书包像素为 `(419,292)`，参考记录为 `data/depth-coverage-chair-backpack-retreat-001/user_click_0004.json`，当时原始深度 737 mm。
采集前核对流分辨率、像素格式、镜像、注册状态、尺度和工厂参数与该参考记录相同。
重新开流后先跳过 30 个接收帧，检查选点仍有合格深度且与原值差不超过 50 mm，随后记录 300 帧。此检查只能排除明显失配，不能证明物体身份或相机姿态未变；实验依赖用户保持场景固定的假设。

每帧使用该像素的真实原始深度，不做空间中位数替换、不补洞、不沿用上一次有效坐标。
沿用已有质量门限：非零、SDK 编码范围内、应用范围 600–4000 mm、3×3 至少 7/9 像素有效、有效邻域极差不超过 `max(10 mm, 2% Z)`、帧年龄不超过 0.5 s、帧号与设备时间单调增加。
合格样本调用官方 SDK 转 XYZ，输出光学约定 X 向右、Y 向下、Z 向前，单位米；不合格时 `position_m=null`，CSV 坐标留空。

同一个程序边预览边采集。第一轮发现间歇失效后，第二轮在同一摆位、同一像素和同一门限下复测，额外保存最初 5 个拒绝帧的完整原始深度，以供定位问题。
两轮之间重新打开流；不将两轮视为一次连续采集。

## 实机结果

| 指标 | 第一轮 001 | 第二轮 002 |
| --- | ---: | ---: |
| 记录帧数 | 300 | 300 |
| 合格帧数 | 280 | 264 |
| 拒绝帧数 / 比例 | 20 / 6.67% | 36 / 12.00% |
| 选点原始零值帧 | 17 | 27 |
| 邻域有效值不足帧 | 3 | 9 |
| 最长连续拒绝 | 2 帧 | 7 帧 |
| 整幅原始深度全零帧 | 0 | 0 |
| SDK 帧序号缺口 | 0 | 0 |
| 设备时间跨度 | 17.902 s | 10.201 s |
| 接收速率 | 16.70 FPS | 29.31 FPS |
| 合格样本 Z 均值 | 737.982 mm | 738.693 mm |
| 合格样本 Z 范围 | 735–741 mm | 735–741 mm |
| 合格样本 Z 样本标准差 | 1.115 mm | 1.154 mm |

速率为本段实际接收帧数与设备时间计算值，不能把 SDK 标称 30 FPS 当作两轮实测值。速率差异原因尚未确定。
标准差使用 `ddof=1`，只对合格样本计算；同时单列所有拒绝样本，不能据此忽略可用率问题。

合格样本的相机 SDK 光学坐标统计如下，单位 mm：

| 轮次 | XYZ 均值 | XYZ 样本标准差 |
| --- | --- | --- |
| 001 | (125.920, 66.140, 737.982) | (0.190, 0.100, 1.115) |
| 002 | (126.041, 66.203, 738.693) | (0.197, 0.103, 1.154) |

固定像素下 X、Y 由同一 SDK 投影模型随 Z 成比例变化，因此这三个标准差不是三个独立方向的绝对准确度实验。
统计保留小数用于复算，不表示物理测量已达到这些小数位精度。
参考点是用户指认书包的可见表面采样点，不是物体中心、姿态或抓取位姿，也不进行目标跟踪。

## 无效值证据与结论

第二轮保存的拒绝帧在选点 5×5 小块中有 16%–72% 零值，同时整幅图零值约 42.2%–42.9%；首张合格帧全图零值约 43.2%。
这些帧显示选点附近有深度空洞，图像其余部分仍有深度。当前证据不能确定是表面条件、观测位置还是采集链路中的哪一因素引起，不能归因为相机损坏。

本轮完成了真实固定像素采集、SDK 转换、质量拒绝和统计。有效读数较集中，但该单点存在 6.67%–12% 拒绝，尚不能作为持续可靠的定位输出。
后续优先采用同一表面区域中的有效点并保留质量门限；若使用区域中位数，必须确认区域主要属于同一表面，且明确它与原固定像素测量的参考点定义不同。不能在零深度像素上直接填入一个“目标位置”。

SDK 主点与工厂主点差异、畸变状态未确认的问题仍未解决；所有本轮记录保留 `geometry_verified=false` 与 `physical_accuracy_verified=false`。
量尺对照按用户意见延后，本轮数据不能证明或否定绝对精度。无机械臂运动或飞行控制。

## 复现与产物

```bash
MPLCONFIGDIR="$PWD/logs/matplotlib" .venv/bin/python camera/astra_pro_plus/point_repeatability.py \
  --selection data/depth-coverage-chair-backpack-retreat-001/user_click_0004.json \
  --output data/backpack-point-repeatability-new --frames 300

# 对已保存的数据重新分析，不连接硬件
MPLCONFIGDIR="$PWD/logs/matplotlib" .venv/bin/python camera/astra_pro_plus/analyze_point_repeatability.py \
  data/backpack-point-repeatability-001
```

输入选择记录只适用于相机与场景保持不动的情况；相机或目标移动后需重新指认，不得直接复用 `(419,292)`。
运行前先关闭其他占用深度设备的程序；正常完成后自动关闭窗口并释放相机，按 Q 可提前停止并保留部分记录。

每轮输出：`session.json`、`samples.jsonl`、`samples.csv`、`point_raw_patches.npy`（逐帧原始 5×5 uint16）、首/中/末帧原始 PGM 与预览、`summary.json`、`capture_status.json`、`repeatability.png`。
第二轮另有 5 组拒绝帧 PGM 与元数据。数据位于本地 `data/`，按项目规则不进入 Git。

已独立读回 600 个样本的原始深度块与 CSV，验证其中心值一致、拒绝样本没有坐标；已核对 6 张完整原始快照与各自帧记录一致。
摘要见 [实机证据核对 JSON](backpack-point-repeatability-2026-11-01.json)。离线质量门限与统计边界自检只用于验证代码，与实机证据分开。
