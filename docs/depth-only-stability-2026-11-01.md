# 单深度实时预览与稳定性检查

日期：2026-11-01。采用现有官方 OpenNI SDK；未运行 IR/RGB 流，未修改曝光、激光、固件或虚拟机控制器配置。

相机由用户放稳，对着墙面或哑光纸板；固定状态及目标类型来自用户报告。
本轮为相机坐标三维选点之前的采集验证，尚未验证绝对准确度、物体中心或抓取点。

## 实现与验证

`scene_preview.py --depth-only` 只创建深度流。实时显示、黄色框统计和原始深度记录在同一进程中进行。
不启动红外，因此与之前双流显示异常分开测试；这只是控制变量，不足以证明旧异常必定由双流导致。
支持按 C 记录 300 帧，也支持代理在预览持续运行时通过控制文件启动指定长度记录。

实际模式：640×480、30 FPS 标称、DEPTH_1_MM uint16、1 mm/原始数值单位，默认镜像开启，图像注册关闭。
黄色框坐标 x=288、y=216、宽64、高48；该框不是分割掩膜，尚未验证其完整属于同一物体表面。
区域中位数只在有效采样主要属于同一表面时具有相应意义。

## 摆放确认前的诊断段

`data/depth-only-live-001/`，450 帧：

- 设备时间跨度 32.337374 秒，按时间戳约 13.8849 FPS。
- 109 帧整幅图没有有效深度，最长连续 100 帧。
- 中途中心深度变化明显；这段在用户确认放稳前启动，不用于静态精度或重复性结论。

## 用户确认放稳后的第一段

`data/depth-only-static-001/`，300 帧：

- 设备时间跨度 9.967913 秒，约 29.9962 FPS，无帧序号缺口、无全零帧。
- 按设备时间排除首 1 秒后，剩余270帧中心像素均有效。
- 中心像素 Z：898–901 mm，中位数901 mm，样本标准差约1.3674 mm。
- 每帧中央框有效比例中位数约96.4844%，范围95.3125%–97.9167%。
- 每帧中央框有效点的深度中位数：898–901 mm，时间样本标准差约1.0645 mm。
- 末帧整幅图有效比例约30.4115%；框外仍有较大无效区，不能称为全视野验收。

原始 PGM 回读为 uint16、480×640；逐帧中央块形状 (300,48,64)，最后一块与末帧原始深度对应区域完全一致。
capture_state 标记记录完成；depth_config 中 IR enabled=false。

这些数值描述该场景下短段读数的变化，不能作为“相机绝对误差约1 mm”的结论。
没有尺子或其他参考真值，也没有完成完整工作距离及图像位置测试。

## 延长记录

`data/depth-only-static-002/`，请求1800帧，用来检查之前出现的中途全零现象是否重现。
这段保持同一深度流、同一预览窗口，已完成：

- 1800帧，设备时间跨度59.974162秒，设备与主机时间计算均约29.996 FPS。
- 无帧序号缺口，无非递增时间戳，无整帧全零。
- 排除首1秒后剩余1770帧，中心像素均有效。
- 中心Z为898–901 mm，中位数901 mm，时间样本标准差约1.4970 mm。
- 中央区域有效比例中位数约96.6146%，范围95.0521%–98.4375%。
- 中央区域逐帧深度中位数为898–901 mm，时间样本标准差约0.9065 mm。
- 末帧整图有效比例约30.4870%，仍不能称为全视野有效。
- 原始uint16 PGM和(1800,48,64)逐帧中央块已回读核对，末帧对应区域完全一致。

该一分钟固定场景下，单深度采集、实时显示和原始数据保存检查通过。
之前记录的无效帧没有被删除或改写；当前较好结果不能证明旧异常根因已经确定，也不能替代其他距离、图像位置和绝对准确度的验证。
数据和图表保存在上述本地目录；提炼结果见同目录文档旁的 JSON 汇总。
