# 第三阶段：书包前景自动定位基础流程通过

## 本次目标与结论

用户要求从重复性检查转入自动找到物体。本次直接运行已有前景定位程序，在当前相机、椅子固定且深度距离适合的场景，完成了一次真实的“空场景 → 放入书包 → 再移走书包”对照。

本次基础流程通过：程序无需用户点选目标，能在新增前景区域中自动选择有效表面像素并给出 SDK 相机坐标；移走物体后掩膜消失，坐标变为无效。不是语义类别识别、物体中心或抓取位姿估计，也不代表绝对精度、RGB 对齐或机械臂对接已验收。

本轮不追加同类固定点重复性测试；此前固定点检查用于发现无效深度和验证拒绝逻辑，绝对准确度按用户意见延后。

## 方法

- 相机与椅子固定，用户先移走书包。单次连续采集中建立 60 帧空背景，满足稳定性条件的背景像素 118,310（全图 38.51%）。不使用旧摆位背景，不在物体存在时学习空背景。
- 当前深度比有效背景近至少 50 mm 才进入前景；原始零值及应用范围外的像素不进入计算。
- 连通域与局部邻域质量门限筛选物体表面，在掩膜内部选择真实有效像素；区域中位深度只用于选点，不替代选点的原始深度，不直接采用框中心。
- 候选满足连续性门限后，调用官方 SDK 转 XYZ；无前景、无有效深度或帧过期时不输出坐标。
- 实际判断的是比背景更近的新增区域。书包的身份由用户说明，程序 `semantic_class=null`，不是训练了书包检测器。手或其他新增物也可能被当作前景，需撤开手。

代码为 `camera/astra_pro_plus/depth_target.py`、`depth_foreground.py` 与已有 OpenNI 桥接，不使用 RGB、YOLO、ROS 或 CUDA。

## 三步实机证据

所有文件位于 `data/depth-target-backpack-stage3-001/`。

| 场景 | 保存记录 | 输出 |
| --- | --- | --- |
| 椅子上无书包 | `chat_snapshot_0001.json` | `NO_FOREGROUND`、mask=0、position=null |
| 放回书包且手撤开 | `chat_snapshot_0003.json` | `STABLE_FOREGROUND_SURFACE`，自动前景掩膜与 XYZ |
| 再移走书包且手撤开 | `chat_snapshot_0004.json` | `NO_FOREGROUND`、mask=0、position=null |

物体存在帧：

- 自动前景掩膜为 50,340 像素，框 `[266,148,288,260]`，截图中覆盖书包所在区域。
- 自动选点 `(409,330)`，与之前人工指认的 `(419,292)` 不同；框中心约 `(410,278)`，也不是当前选点。
- 选点原始深度为 733 mm，背景同像素为 940 mm，比背景近 207 mm；选点在前景掩膜内部，原始深度与 JSON 读回一致。
- SDK 光学坐标约 `(112.436,113.699,733.000)` mm，JSON 输出米为 `(0.112436,0.113699,0.733)`。
- XYZ 原点采用 SDK 深度相机光学模型，X 右、Y 下、Z 前；原生 SDK 的 Y 明确反号。不是机械臂基座坐标。
- 此点是可见表面采样点；候选像素可随帧改变，不作为同一物理点的重复性统计，也不作为书包中心。

已重新读回三种场景的 uint16 原始 PGM 和掩膜 PNG，核对前景面积、像素原始值、背景差及无前景坐标为空。机器可读摘要见 [验收证据](stage3-backpack-auto-2026-11-01.json)。

## 复现

```bash
# 先关闭其他占用深度相机的程序，并移走目标、保持相机和背景固定。
.venv/bin/python camera/astra_pro_plus/depth_target.py \
  --output data/depth-target-new --auto-background
```

背景采完后放入目标并撤开手。左侧显示深度与候选框，右侧灰色是可比较背景、白色是前景掩膜；绿色框和 XYZ 表示满足当前质量/时间门限。
`B` 重新采空背景（先移走目标），`S` 保存当前原始深度、掩膜、预览和 JSON，`Q` 退出。
代理也可用 `--control` 指定的本地 JSON 控制背景采集、快照和关闭；本次未要求用户按键采背景或手动选择目标。

## 验收边界与下一步

本次通过限定为当前固定场景中的一次放入/移走流程，不承诺其他材质、距离、多个物体或移动相机场景的泛化能力。
背景中原本无效的像素不能参与深度差；大范围场景变化、多候选歧义等会拒绝输出。这些属于方法适用条件，不能靠放宽阈值掩盖。
SDK 模型与工厂主点差异、畸变状态未确认仍存在，`geometry_verified=false`、`physical_accuracy_verified=false` 保留。

后续可继续完善前景区域质量、输出接口和目标选择，再按实际需要接入类别检测/分割。量尺绝对准确度对照、RGB、坐标系标定与真实机械臂操作分别保持原有未完成状态。
