# RGB 指定区域到原始深度表面点 XYZ

设备仍为 Astra Pro Plus；Ubuntu 22.04.5 / VMware xHCI，OpenNI 2.3.0.86-beta6。代码入口为 `camera/astra_pro_plus/rgb_roi_xyz.py`，复用项目 `.venv`、OpenCV 4.5.4 和已编译的官方 SDK 桥接库，无新增系统依赖。

## 本次完成与实机证据

用户在真实彩色预览中拖框，确认出现 XYZ。完成了 RGB 入口的基础链路；这与此前只在深度图中选点、或用深度背景差分提取书包，是不同的入口。

最后修正版本的首个实机有效样本保存在本机 `data/rgb-roi-xyz-003/first_valid_0001.json`：

| 项目 | 实测值 |
| --- | --- |
| RGB 选区 xywh | (387, 250, 72, 82)，恢复自用户最后一次拖框 |
| 原始深度像素 uv | (439, 326) |
| SDK D2C 对应 RGB 像素 | (417, 317)，在选区向内缩6像素后仍位于框内 |
| 原始深度 | 717，DEPTH_1_MM，Z = 0.717 m |
| SDK XYZ，米 | (0.1470544281, 0.1062746201, 0.717) |
| 3×3 邻域 | 9/9 有效，深度极差4 mm |
| RGB / Depth 主机读取返回时间差 | 约32.3 ms；不是曝光时间差证明 |

该 XYZ 表示一个可见表面采样点。程序使用原始 SDK 深度坐标转换，再反转原生 Y 符号，输出 `camera_depth_optical_sdk`：原点为 SDK 深度相机模型原点，X向右、Y向下、Z向前，米为单位。工厂主点与 SDK 反投影模型的差异、畸变状态及物理准确度仍未解决，继续标记 `geometry_verified:false`、`physical_accuracy_verified:false`。

同时保存真实 RGB PNG、未缩放未填洞的 uint16 深度 PGM、深度域候选掩膜 PNG。首个会话和第二个会话也保存了有效样本。第二个会话已检查保存帧中的原始像素值814与记录一致，XYZ.Z=0.814 m，SDK 对应像素在用户框内。随后通过代理控制清空选区，实机 `latest.json` 返回 `RGB_BOX_REQUIRED`、`valid:false`、`position_m:null`；控制行为记录为 `AGENT_DIAGNOSTIC_CLEAR`，没有冒充用户操作。

运行过程中用户继续改变选区。程序重启时保留最新用户选区，未要求重复摆放目标。本地现场图像与原始数据由 `.gitignore` 排除，不上传到 GitHub。

## 计算路线

1. 深度640×480、1 mm/raw、镜像关闭、硬件注册关闭；UVC 彩色640×480 MJPG 解码为 BGR，不额外翻转。
2. 从本机 SDK 读取实际30个工厂参数，用深度内参、R/t、彩色内参向量化筛选投影进 RGB 框的原始深度点。该模型不额外套用未知状态的畸变校正，仅用于候选筛选。
3. 启动时用9组模拟 uv/Z 输入核对模型与官方 SDK 像素 D2C 查询；本次9组整数像素差均为0。这是接口一致性检查，不能当作实物标定或实际配准精度。
4. 在 RGB 框内保留原始有效深度，做投影遮挡筛选，按相邻像素明显的深度突变切断连接。选择最大连续实测表面片；若另一个大小相近的独立表面片深度相差明显，拒绝自动决定目标层。
5. 在表面内部、接近该片深度中位数的范围寻找真实像素；深度始终使用该像素原值，不以中位数替代。要求3×3邻域至少7/9有效且极差不超过 max(10 mm, 2% Z)。这些是当前经验门限，不是精度认证。
6. 所选点必须再通过官方 `PIXEL_D2C_REGISTRATION` 查询，SDK 对应 RGB 像素在缩小后的用户框内，且与候选投影差不超过2像素。最终 XYZ 只使用原始深度 uv/Z；没有将 RGB uv 或硬件注册后的像素交给原始深度 XYZ 转换。
7. 至少3个不同深度帧、持续至少0.25秒通过检查才输出；无效立即为空，不保持上次 XYZ。按主机返回时间粗配对（差<0.2 s，帧龄≤0.5 s），尚无硬件同步证明。

## 用户反馈：为什么 XYZ 出现后又消失

用户实际看到 `XYZ unavailable: no previous coordinates retained`。这表示当前测量未通过检查，不是异常崩溃；不能据此断定相机损坏或 Ubuntu 不兼容。日志中既有深度不足，也有多个候选深度表面竞争。即使目标不动，局部空洞变化也可能使候选支持不足。

开发中发现旧的全局深度直方图筛选会错误拒绝跨度较大的连续斜面：模拟800–1200 mm连续表面返回 `NO_SUPPORTED_DEPTH_LAYER`。已改用局部深度连续性连接，模拟回归通过；正常曲面不要求所有像素有相同Z。仍然保留独立远近表面竞争、边缘突变和无效深度的拒绝。改后实机既有有效样本，也仍有间歇拒绝，**尚不能宣称稳定目标跟踪已完成**。

GUI 现在显示具体原因，如“缺少可靠局部深度”或“多个独立表面，请选择目标表面”，同时保留无效时坐标为空的行为。框选只是用户指定图像区域，不提供书包语义、质心、姿态或抓取点；大框混入椅子时，不保证自动选择书包。选区也不随移动物体跟踪。

## 验证范围与复现

9项模拟离线检查覆盖有效面、无深度、无选区、选区过小、空洞、较小的近处杂物、断开的同深度片、连续斜面、独立远近平面竞争。另有既有8项原始深度质量检查。模拟结果与上述真实相机样本分开记录。

```bash
.venv/bin/python -c "import sys; sys.path.insert(0,'camera/astra_pro_plus'); from rgb_roi_depth import self_check; print(self_check())"
.venv/bin/python camera/astra_pro_plus/rgb_roi_xyz.py --output data/rgb-roi-xyz-new --seconds 900
```

实时输出 `latest.json`，逐次测量为 `observations.jsonl`，首个有效结果自动保存原始帧；S手动保存，C清空，Q退出。保存帧与测量使用同一组数据，退出后 `latest.json` 无效。后续改进应围绕明确的目标表面选择、间歇深度缺失及配准误差展开；本次没有执行真实机械臂运动。
