# 阶段 3：固定相机深度前景分割

本文保留早期未通过的开发与实机对照。相机后移至合适距离后，已另行完成一次基础前景定位流程，最新结果见 [书包自动定位验收](stage3-backpack-auto-2026-11-01.md)。RGB 按用户决定暂缓，未训练 YOLO，也未识别物体类别。

## 方法与运行

```bash
# 从仓库根目录运行；先关闭其他占用深度设备的程序。
# 相机固定，先移走目标，保留静止背景。输出目录必须新建。
.venv/bin/python camera/astra_pro_plus/depth_target.py \
  --output data/depth-target-new --auto-background
```

左侧为深度伪彩色图，黑色包括无效深度及被当前工作范围筛掉的像素；右侧灰色为可比较的背景，白色为前景掩膜。
采集空背景时保持场景不动。背景就绪后，放入比背景更近的哑光物体，撤开手。
`B` 在当前场景重新采集空背景，`S` 保存当前原始深度与结果，`Q` 退出。
重新采集空背景前必须移走目标；每次开始新的采集会话，推荐重新采集空背景。

- 连续采集 60 个原始深度帧，逐像素计算时间中位数。只采用至少 80% 帧有效且波动较小的像素；背景中无效的区域不能凭空用于深度比较。
- 当前工作范围为 600–4000 mm，属于应用筛选范围，不是经过验证的硬件准确度承诺。原始 0 拒绝使用。
- 当前有效像素比同一位置背景近至少 50 mm，才进入候选。排除小连通区域、明显多目标歧义和大面积场景变化。
- 从前景掩膜内部选一个真实有效像素，检查其 3×3 邻域深度一致性；区域中位数仅帮助选点，不替代该点原始深度，不补洞，不直接查询框中心。
- 连续至少 8 个处理结果且持续至少 0.5 秒满足位置与深度连续条件，才输出 SDK 模型 XYZ。时间连续只表示检测持续，不能证明目标身份。
- 相机坐标系为深度相机光学约定：X 向右、Y 向下、Z 向前，输出米。原生 SDK 的 Y 向上，程序明确反号。

这里依赖固定相机、静止背景、目标比背景更近的假设。手、其他近物、移动的背景、失配的旧背景都可能成为前景；这不是语义识别，也不是通用桌面分割。

## 实机记录

1. `data/depth-target-stage3-001/` 采集了 60 帧空背景，仅 28,680 像素（全图 9.34%）满足背景条件。空场景结果为 `NO_FOREGROUND`。之后进程退出，状态文件停止更新，不能把旧状态当作当前测量。
2. `data/depth-target-stage3-002/` 恢复预览并加载原背景。实际读取了相同流配置、工厂参数与镜像设置后才允许加载，没有把已放入的目标重新学成背景。
3. 在 `(508,247)` 选到原始深度 741 mm，SDK 光学坐标约 `(240.1,8.9,741.0)` mm；对应旧背景为 809 mm，差 68 mm。前景掩膜 7,171 像素，选点在掩膜内、邻域 9/9 有效。已保存同帧 uint16 PGM、掩膜、预览和 JSON，并重新读盘核对。
4. 用户移走物体后仍检测到相同区域。用户确认该区域是背景、相机和背景未移动。因此上项只能证明检测到深度变化区域，不能作为成功识别该物体的证据，移走后的负例验收失败。原始帧确实更新，排除了状态文件陈旧；旧背景与当前空场景存在空间上不同的数厘米差异，来源尚未确定，不能归因为硬件损坏。
5. 已在同一次连续采集中重新采集用户确认的空背景 `background_002`，可比较像素 37,644（12.25%）。随后至少 472 个处理结果连续为 `NO_FOREGROUND`；`chat_snapshot_0005` 重新读盘核对为无前景、掩膜零像素、坐标 null。这证明新背景下的空场景负例通过；仍需重新做目标放入与移走对照，不能代替该测试。
6. 用户重新放入物体后，`chat_snapshot_0006` 为 `INSUFFICIENT_CURRENT_DEPTH`，坐标 null。原始帧 260,516 像素为零，40,448 像素非零但小于 600 mm，6,236 像素处于工作范围内，与有效背景重叠仅 1,928 像素，低于 3,000 像素门限。检查位置发现中央原背景区域主要为零，周边有约 450–500 mm 读数，不能把周边值当作物体距离。用户表示现有位置没有空间将物体后移，因此需要可固定相机、目标间距足够的新布置；本次实机正例仍未通过。
7. 本轮预览已通过控制文件正常关闭，进程退出码 0；读盘确认 `latest.json` 为 `SESSION_CLOSED`、`valid=false`、`position_m=null`。数据全部保留，等待确认新摆位条件；RGB 排查仍暂缓。

原始帧核对摘要见 [实机证据核对](stage3-snapshot-verification-2026-11-01.json)。现场数据按项目规则存于本地 `data/`，不进入 Git。

## 输出与限制

`session.json` 保存真实流配置、实际参数、算法阈值与坐标定义。
`background_*.npz` 是可用背景模型，`background_*_raw_frames.npy` 保留建立该模型的原始帧。
`observations.jsonl` 与 `latest.json` 输出时间戳、帧号、有效性、原因、掩膜/点信息及坐标。
快照保存该帧原始 16 位 PGM、分割掩膜 PNG、预览 PNG 和 JSON，伪彩色不参与计算。
外部读取者必须检查有效性以及主机时间的新鲜度，不能复用过期坐标；正常退出会将 `latest.json` 标为 `SESSION_CLOSED`。强制终止或断电时仍应依赖时间戳失效。
当前代码增加了超过 0.5 秒无新帧时主动撤销坐标、清空稳定计数并显示警告，以及输出零值/工作范围/可比较像素计数；会话 002 是修改前已启动的进程，这两项新增诊断尚未在断流实机条件下验收，下一次启动生效。

`--load-background` 可用于诊断恢复，必须保持相机和背景不变；即使流配置与内参相同，也不能保证旧背景仍适用。本次已实际遇到失配，不推荐把它作为常规启动路径。

`valid=true` 仅表示当前分割、深度与时间门限通过。结果是可见表面的一个采样点，不是物体中心、物体姿态或抓取位姿。`semantic_class=null`。
阶段 2 发现的工厂主点与 SDK 模型差异、畸变状态未确认的问题仍未解决，输出保留 `geometry_verified=false` 和 `physical_accuracy_verified=false`，不得据此驱动机械臂。

离线自检含 10 类人工构造场景，明确标为 `SIMULATED_OFFLINE`；它们用于检查拒绝逻辑，不能替代实机正例与负例。
