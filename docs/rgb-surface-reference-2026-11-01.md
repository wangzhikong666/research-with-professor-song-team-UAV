# 参考表面连续测量与局部零深度诊断

本次改进针对 RGB 框选后 XYZ 频繁消失。沿用 Astra Pro Plus、OpenNI 2.3.0.86-beta6、Ubuntu 22.04.5、VMware xHCI；未安装新SDK或训练模型，未改固件或发送机械臂指令。

## 已确认的问题与改动

旧策略每帧重选全框最大连续表面，遇到大小接近的不同深度片就拒绝；跨帧门限又比较可能来自不同部位的Z。这会造成选择跳变和反复等待。新版增加明确的用户参考表面：

- 左键拖 RGB 框，右键点框内目标表面。初始只在点击位置半径12个RGB像素内寻找局部质量合格、经官方SDK D2C验证的原始深度点；点击落在两层边界时仍可拒绝。
- 固定首次通过 SDK 检查的原始深度像素和初始Z约束。首次需3个不同深度帧、至少0.25秒通过检查；之后各帧独立测量，不因一次缺失反复从头等待确认。
- 优先同一原始像素。无效时只搜索固定参考像素半径4个深度像素内的实测邻点，并要求其深度处于初始Z ± max(30 mm, 3% Z)，RGB对应点仍在指定位置半径12像素及缩小后的框内。初始深度约束保持不变，不随结果逐步漂移到别的表面。
- 邻域仍要求3×3至少7/9有效、极差≤max(10 mm, 2% Z)。邻点代替采样位置时，`same_original_depth_pixel:false` 和 `sample_offset_from_reference_depth_px` 明确说明；不是给无效原像素补一个假深度。
- 当前无合格深度则 `valid:false, position_m:null`。保留的是参考选择约束，XYZ始终来自当前测量；深度恢复后可以自动恢复输出，深度明显改变时要求恢复场景或重新选择。

窗口显示参考像素、当前原始值、实际采样偏移及可用更新数。输出仍为 `camera_depth_optical_sdk`（右/下/前，米）的一个可见表面采样点。邻点属于同一表面是局部假设，不证明同一物理点、对象身份或抓取意义。相机/物体运动时不能将固定像素当成目标跟踪，需重新选择或后续接入跟踪/分割。

## 同一批真实帧的新旧策略对照

`--compare-baseline` 对同一原始深度帧运行旧的最大表面及跨帧深度门限，以及新的参考表面策略；都执行原生SDK像素检查，使用相同的帧时效条件。它比较两种选点策略的可用率，参考点定义有所不同，不是坐标精度对照。

本机 `data/rgb-surface-reference-001/` 中，用户最后一次右键点击 RGB (424,313)，固定原始深度参考 (445,321)，初始Z=715 mm。初次由代理从先前样本选择的诊断参考单独标记为 `AGENT_DIAGNOSTIC_FROM_PRIOR_SAVED_SURFACE_SAMPLE`；用户后续多次右键选择分别分组，没有混作用户操作。

| 指标：用户最后一个参考，同1441个不同深度帧 | 结果 |
| --- | --- |
| 新策略有效输出 | 643 / 1441 = 44.62% |
| 旧策略有效输出 | 79 / 1441 = 5.48% |
| 新策略在原参考像素采样 | 592个有效帧 |
| 新策略使用受限邻点 | 51个有效帧 |
| 新策略当前局部深度缺失/不可靠 | 796帧 |
| 缺失后自动恢复的次数 | 306 |

`analyze_surface_reference.py` 对所有有效记录检查：XYZ有限、Z与本帧原始深度单位转换一致、源像素距参考≤4、Z在固定初始范围内、SDK对应像素仍在RGB框及参考附近。所有无效记录坐标为空；保存的有效PGM为原始uint16，原像素值与JSON一致。完整会话有4组有效原始帧留档。用户截图也显示相同参考像素有坐标/无坐标交替。

结论：软件选择连续性已有改善，**连续可靠的实物定位尚未通过**。剩余失效大量来自真实原始深度缺失，不能通过保留旧XYZ宣称解决。

## RGB 并发开关对照：原始深度确实缺失

用户发现深度伪彩图中书包区域交替变黑。伪彩图黑色也包括应用过滤掉的距离，因此进一步直接检查原始数据：一张失效帧在参考点周围9×9全为0，半径12的邻域也全无深度。

保持原场景，用 `depth_dropout_probe.py` 顺序测试RGB开、关；均为相同的原始深度模式、参考像素 (445,321)，预热2秒后采15秒，并固定对照像素 (393,147)。本机证据在 `data/depth-dropout-rgb-on-001/`、`data/depth-dropout-rgb-off-001/`，每组保留CSV及零/非零原始帧。

| 指标 | RGB开 | RGB关 |
| --- | --- | --- |
| 测得深度帧数 | 450 | 450 |
| 参考像素为零 | 72.22% | 90.22% |
| 参考周围9×9全零 | 70.67% | 90.00% |
| 参考像素通过原有3×3质量检查 | 27.11% | 9.56% |
| 对照像素非零 | 100% | 100% |
| 整帧全零 / SDK帧序号缺口 | 0 / 0 | 0 / 0 |

关闭RGB后失效仍存在，不能把RGB并发视为这个现象的必要条件。两次为顺序采样、未反复随机化，不能据此认定关闭RGB使测深变差。固定对照点正常、局部原始值为零更支持局部测深困难；尚未单独排除所有USB、驱动或设备问题。帧序号缺口只是观测指标，不能独立证明USB链路完美。

## 原理、下一项物理对照与限制

[Orbbec官方Astra系列说明](https://www.orbbec.com/products/structured-light-camera/astra-series/)明确包含Pro Plus，采用红外结构光，标称深度范围0.6–8m。通过投射红外图案并从几何对应关系估计深度，要求表面反射出可用图案。RGB图正常不保证红外测距有效；当前有效Z约715 mm，高于标称下限，但范围内也不保证任意材质、姿态和光照都有深度。

[Intel深度测试方法第2.6节](https://www.realsenseai.com/wp-content/uploads/2019/11/RealSense_DepthQualityTesting.pdf)讨论结构光等红外系统受材质红外反射、深色织物和环境光影响的通用问题。它不是Astra型号专属验证。书包的织物反射、曲面褶皱、背带遮挡和环境光是待验证候选原因；不能仅凭RGB看起来黑就断定红外吸收，也不能凭截图判断相机损坏。

用户随后确认白纸已固定、手已撤开，RGB留档可见白纸覆盖书包指定区域。在相同原始参考像素 (445,321)、对照点 (393,147)、RGB开启配置下重新预热并采15秒，完整数据在 `data/depth-dropout-white-paper-002/`：

| 指标 | 原书包表面，RGB开 | 白纸表面，RGB开 |
| --- | --- | --- |
| 深度帧数 | 450 | 450 |
| 参考像素为零 | 72.22% | 28.00% |
| 参考9×9全零 | 70.67% | 27.33% |
| 参考像素通过3×3质量检查 | 27.11% | 72.00% |
| 对照像素非零 | 100% | 100% |
| 整帧全零 / SDK帧序号缺口 | 0 / 0 | 0 / 0 |

白纸改变后的表面条件明显改善了本次测深可用率，但仍有缺失。白纸有弯曲并比原布面更靠近相机，非零读数682–687 mm，原参考初始值为715 mm；该对照同时改变了反射、平整度/姿态及局部距离，不能把改善仅归因于可见光颜色或仅凭此认定唯一根因。下一项宜固定该易测表面，单独改变光照或角度，继续判断剩余缺失；暂不盲改红外增益、曝光或投射器参数。

第一次白纸采集 `white-paper-001` 收到进程终止信号，只保留330行部分CSV和原始帧，未生成完成报告；它未计入上表，未用其中较高的有效比例代替完整测试。程序使用新目录重采450帧并正常退出。

白纸表面与原布面位置不同，旧参考的深度范围曾正确触发 `REFERENCE_DEPTH_CHANGED_RESELECT`。随后为已声明改变的表面新建会话并重新获取当前参考，而没有扩大旧约束或复用旧XYZ。`data/rgb-surface-reference-004/` 保留恢复后的白纸预览，初始参考原始像素 (447,321)，Z=682 mm；一组当前实测XYZ为 (0.1494983521, 0.0953493271, 0.683) m。这是纸表面点，不是原布面同一物理点，也不是书包中心。

几何畸变状态、SDK主点模型差异、RGB曝光同步及绝对准确度仍未验证；继续保留相关false标记。没有使用插值、时间保持或学习模型生成的深度替代真实测量。

## 复现与离线检查

```bash
.venv/bin/python -c "import sys;sys.path.insert(0,'camera/astra_pro_plus');from surface_reference import self_check;print(self_check())"
.venv/bin/python camera/astra_pro_plus/rgb_roi_xyz.py --output data/reference-new --compare-baseline
.venv/bin/python camera/astra_pro_plus/analyze_surface_reference.py data/reference-new
# 相机不可被其他程序占用；物体和相机保持固定。两次参考与对照像素相同。
.venv/bin/python camera/astra_pro_plus/depth_dropout_probe.py --reference 445 321 \
  --with-rgb --output data/dropout-on-new
.venv/bin/python camera/astra_pro_plus/depth_dropout_probe.py --reference 445 321 \
  --control-pixel 393 147 --output data/dropout-off-new
```

新增9项模拟离线检查覆盖多层表面指定、不同帧的初始确认、固定像素优先、受限邻点、失效/恢复、错误深度层拒绝、重新选择、选区边缘和连续斜面。这些检查与上面的真实相机结果分开。
